The sigma seam — why the harness becomes the camp's spine

This is the single highest-leverage move in the plan, and it will feel familiar to anyone who has designed a service boundary. The PIs' central decision diagram wants a per-image uncertainty number (called sigma, σ) that says "how unsure is the model about this one image?" — used to route uncertain images to a human reviewer. But uncertainty estimation is other people's job: three subgroups will build it (MC-Dropout, deep ensembles, evidential heads). It is also literally Sournac's research area.

The boundary rule, stated once
THEIRS = producing the sigma array — the forward passes, the ensemble members, the scale choice, running it under attack.
OURS = the schema, the validation, the rank-based scoring, the fitted-and-frozen policy, the degeneracy audit, the demo display.
The boundary is the .npz file. One file format lets one person score the PIs' own research area without ever building — or arguing about — an estimator.

In distributed-systems terms: this is defining the message contract at an integration seam. You do not import the other team's code or depend on their internals; you publish a schema, validate anything that arrives against it, and everyone who wants to be scored conforms to your wire format. The npz today already carries predictions, labels, and a per-split checksum. The seam adds one optional field and a mandatory sidecar describing it.

sigma   float32[n]   OPTIONAL — per-image uncertainty, higher = more uncertain

"sigma_semantics": {
  "method":      "mc_dropout | deep_ensemble | evidential | ...",
  "n_samples":   <int>,             // MC passes or ensemble members
  "scale":       "predictive_entropy | variance | ...",
  "higher_means":"more_uncertain",   // literal; producers convert, WP1 never flips
  "seed":        <int>
}

Three contract rules make the owner the referee rather than a competitor:

  • Sigmas of different scale are never compared in one table (same discipline as never mixing batch sizes).
  • Sigma thresholds are fitted per model on clean calibration data and then frozen — exactly like the moderation thresholds already are.
  • A submitted sigma must beat the plain-confidence baseline through the frozen policy to count. If a team's sigma is secretly just a function of the softmax confidence, the two-axis policy provably collapses to the one-axis policy — the same temperature-invariance result that appears elsewhere in the project. A useless sigma is detected and reported, never silently accepted.
Why publishing it on Day 1 wins
Whoever owns the contract owns the integration. If the schema is published on Day 1 and demoed live ("here is what your MC-Dropout npz looks like; here is the table it prints"), then every subgroup's output arrives in the owner's format from the start — and the harness is the scoreboard, not a competitor. The full seam is ~13 hours of pure-CPU, zero-GPU work; only the one Day-1 push needs the network. Everything after the schema itself is plane-capable.

The ResNet floor, framed correctly
The frozen ResNet probe will score well below the CLIP L/14 probe (0.9291 clean, the harness page). That is the expected literature ordering — CLIP features beat supervised-CNN features for fake detection. It must be presented on Day 1 as the floor that motivates the camp's fine-tuned ResNet, not as a weak result to be discovered by someone else later.

Owner decisions — options and a recommendation

These are the four choices only the owner can make; each has a recommendation and a reason.

Licence for the brick

RecommendedApache-2.0 — explicit patent grant, the default for research-consortium artifacts, least friction for "is this a TRAIL Factory brick?" AlternativesMIT/BSD-3 (max reuse, no reciprocity); MPL-2.0 (file-level copyleft); AGPL-3.0 anti-recommended — it deters the very organizations the Factory serves. FlagThe Prototype Fund grant's open-source bar may constrain what is shared with that dossier — check before signing a licence. No LICENSE file exists yet (verified).

Repo visibility
