Glossary

Every term this wiki uses, defined in a sentence or two, with a link to the page that explains it in depth. Reference, not prose — skim to the letter you need.

How to read the numbers
Where a definition carries a number it is grounded in a file under FILES/PROJECTS/trustfake/wp1. The two that recur: the CLIP probe scores acc 0.9289 / AURC 11.83e-3 on the clean test slice (n = 15,316, verified from runs/predictions/…vit_large…test_clean.npz), and the EfficientNet probe scores acc 0.8311 — held bit-identical while ACE collapses its ranking. See the harness for what each metric measures.

A

Abstention — a moderation pipeline declining to auto-decide an image and routing it to a human instead. Driven by a confidence threshold: below it, review; above it, auto-act. The whole selective layer is a rule over abstention. See moderation.

ACE (Attack on Confidence Estimation) — an adversarial attack that moves a detector's confidence without changing its prediction: it pushes down the confidence of correct answers and up the confidence of wrong ones, accepting a per-sample step only if the argmax is unchanged (Galil & El-Yaniv, Algorithm 1). Accuracy stays fixed to 4 dp by construction while ranking is destroyed. See attacks.

AUGRC (area under the generalized risk-coverage curve) — the weighted mean of generalized risk across operating points. Because generalized risk divides by n rather than by the accepted count, AUGRC does not blow up as coverage approaches zero, unlike AURC. The Traub et al. metric; implemented in metrics.py. See the harness.

AURC (area under the risk-coverage curve) — the weighted mean of selective risk across every operating point; lower is better. Dominated by the low-coverage tail, where the error estimate rests on a handful of samples. This harness averages over tie-collapsed operating points (weights='block'), which reduces to the textbook definition when all confidences are distinct. See the harness.

AUROC (detection) — area under the ROC curve for the detection task: does p(fake) rank fake images above real ones. This is the classifier-quality number (CLIP clean = 0.9801). Not to be confused with the failure-prediction AUROC — every table must say which one it shows. See the harness.

AUROC (failure prediction) — area under the ROC curve for the failure task: does confidence rank the model's correct predictions above its own mistakes. 0.5 is chance; a confidence attack drives it toward 0 (near-perfect inversion), which is worse than useless because the abstention rule then preferentially rejects the correct answers. ACE takes it 0.7703 → 0.0002. See attacks.

B

Batch-shape non-determinism — EfficientNet under cuDNN is not bit-identical across batch shapes, so re-running a model on the same images in a different batch flips a boundary sample and reads label-preservation 0.998 instead of 1.0 for reasons unrelated to the attack. The harness fixes this by reporting the logits from the accept-check forward pass, never a re-run. See how experiments lie.

C

Calibration — how well a model's stated confidence matches its actual accuracy (a "90% confident" bin should be right 90% of the time). Central caveat of this project: for a binary abstention rule, calibration is not a defence — temperature can rescale confidence without changing the ranking the rule depends on. See the harness and how experiments lie.

CLIP ViT-L/14 probe — the stronger of the two detectors: a frozen CLIP vision transformer with a linear head fitted on its features (UniversalFakeDetect recipe). Clean test accuracy 0.9289, AURC 11.83e-3. Being a linear probe, its logit margin is small (≈13) and its AURC is temperature-invariant. See the project.

Coverage — the fraction of traffic the model auto-decides at a given confidence threshold (cov = accepted / n). The other axis of the risk-coverage curve; the complement of the review rate. See the harness and moderation.

D

Decode cache — the on-disk store of decoded images (uint8 JPEG), keyed by uid, that every experiment reads from so results are reproducible and the parquet shards are touched once. Because it is uint8, pixels sit exactly on the k/255 grid — which is why a sub-step ACE perturbation vanishes when re-saved. See the dataset.

Decode-scale threshold — a model-free rule on the decoded image's dimensions (a laundered form of the geometry shortcut). Scores 0.9798 on the test split with no network at all — slightly above the width==height rule's 0.9785. Evidence that raw accuracy on SID-Set is not evidence of forensic capability. See the dataset.

E

E-AURC (excess AURC) — AURC minus the AURC of the oracle ranker on the same sample; zero for a perfect ranker. Isolates ranking quality from the base error rate — but only partly, so it is used as a within-model diagnostic beside AURC, never for cross-model claims (those ride on AUROC-failure, which is rate-free). See the harness.

ECE (Expected Calibration Error) — the mass-weighted gap between confidence and accuracy, summed over confidence bins. Reported, but treated with suspicion: it is biased upward by binning (a perfectly calibrated binary model reads ~0.006 at 5 bins, ~0.057 at 200), so NLL and Brier score are printed alongside it. See the harness.

EfficientNet-B0 — the second, weaker detector: a small convolutional backbone with a linear head (clean accuracy 0.8311). It is the target of the confidence attacks because its backward pass is cheap and its features are cached offline. Fine-tuned into three defended arms (standard, PGD-AT, TRADES). See attacks and defenses.

F

Forensic epsilon — the small perturbation budget (roughly 1–4/255) at which the defenses are trained, chosen because deepfake evidence is itself small-amplitude. The larger textbook budget of 8/255 collapses this task (the PGD-AT arm degenerates to a constant output, both accuracies 0.4943), so the forensic regime is a requirement, not a convenience. See defenses.

G

Generalized risk — the error count among accepted samples divided by n (the whole set), as opposed to selective risk which divides by the accepted count. The quantity AUGRC integrates; the identity R_gen = coverage × R_sel holds elementwise. See the harness.

Geometry shortcut — the label leak in SID-Set: every synthetic image is a square 1024×1024 PNG and every tampered one is square, but only 4.3% of real images are, so "width==height → fake" scores 0.9785 with no model. Our pipeline resizes to 224×224 so it cannot read the ratio directly; a square-crop control confirms the model isn't riding the raw ratio — but not that it isn't riding the laundered compression signature (an open problem). See the dataset.

Gradient masking — when a defended model looks robust only because the attack's gradient is uninformative, not because the model is actually hard to fool. Suspected here because ACE's effective epsilon reaches only 64% of its budget on the PGD-AT arm — a possible artefact, and the reason the "AT protects confidence" claim is flagged as a question for the PIs rather than a result. See how experiments lie.

I

img_id vs uid — img_id is the dataset's own image id and it is not unique: 8,634 ids recur, and 19,107 collide across splits (10,000 synthetic + 9,107 tampered). Keying a cache on it silently merges the wrong rows. The global key is uid = "<source_split>:<img_id>"; join on uid, use img_id for traceability only. See the dataset.

L

Label-free attack — an attack that uses no ground-truth label, so a real attacker (who cannot see labels) can actually run it. The over-confidence attack (Ledda et al.) is label-free: it freezes the clean prediction and pushes probability mass toward it, making the model confidently wrong where it was quietly wrong. This is exactly ACE's practical weakness — ACE needs the label. See attacks.

M

Margin — the difference between the two class logits, z1 − z0. For a binary model, confidence is a monotone function of the absolute margin, which is why temperature (a rescale of the margin) cannot reorder samples. The linear probes have small margins (max ≈12–13); the trained checkpoints reach ≈118, which is what breaks their temperature-invariance. See the harness.

MSP (Maximum Softmax Probability) — the default confidence score g(x): the largest class probability after softmax. For two classes MSP = sigmoid(|margin| / T), strictly monotone in the margin — the single fact behind the temperature-invariance result. Any entropy or energy score can be swapped in; the harness never assumes MSP. See the harness.

N

n_op (number of operating points) — the count of distinct confidence values, i.e. the number of thresholds the risk-coverage curve actually has. The guard rail: if it collapses far below n, fp16 softmax has saturated to exactly 1.0 and manufactured tie blocks, and AURC is no longer a property of the model but of the sort order. A saturated cell makes AURC temperature-dependent. See how experiments lie.

O

Operating point — one achievable (coverage, risk) pair on the risk-coverage curve, existing only at a distinct confidence value (tie blocks collapsed). A threshold falling inside a tie block is never evaluated, because the set it would accept depends on the sort permutation. See the harness.

P

PGD (Projected Gradient Descent) — the standard prediction-targeted attack: iterate the gradient of the loss and project back into an epsilon-ball to flip the label. Used here for contrast — it destroys accuracy (standard model → 0.0000 under PGD 2/255), the opposite signature to ACE, which leaves accuracy intact. See attacks.

PGD-AT (PGD adversarial training) — a defense that trains on PGD-generated adversarial examples. At the 2/255 forensic budget it holds accuracy under attack (0.7192 vs the standard model's 0.0000); at 8/255 it collapses to a constant output. One of the three defended arms. See defenses.

Prediction- vs confidence-targeted — the two orthogonal failure modes. A prediction-targeted attack (PGD) or a realistic corruption (JPEG, downscale) destroys accuracy while ranking survives; a confidence-targeted attack (ACE, over-confidence) leaves accuracy identical and destroys ranking. Only printing accuracy beside AURC tells them apart. See attacks.

R

Residual risk — under a moderation policy, the error rate that survives among the images the pipeline still auto-decides (the ones it did not send to review). The deployment-facing number: at a 5% SLA the file-realisable ACE attack drives it to 33.06% on the EfficientNet probe, while on the CLIP probe it rises only 5.46% → 7.46% because a low base error rate bounds the damage. See moderation.

Review rate — the fraction of traffic routed to human review, 1 − coverage. The cost axis of the selective layer: holding an SLA under attack pushes it from ~27% to ~50%, and that doubling of human workload is the price of the guarantee. See moderation.

Risk-coverage curve — the fundamental plot of the harness: selective risk (error rate among accepted samples) as a function of coverage (fraction accepted), swept over the confidence threshold. AURC and AUGRC are areas under it. See the harness.

S

Selective risk — the error rate among the samples the model accepts at a given threshold: errors(accepted) / count(accepted). The quantity AURC integrates; it blows up at low coverage where the denominator vanishes. See the harness.

SID-Set — the dataset: real images, fully-synthetic images, and tampered (locally edited) images, folded to a binary real-vs-fake task for a social-media moderation pipeline. All numbers here are on the validation slice (n = 15,316) — the official test split is withheld by the authors. See the dataset.

SLA (Service-Level Agreement) — the maximum error rate the moderation pipeline is contracted to hold on the images it auto-decides (e.g. 5%). The selective layer picks the confidence threshold that keeps selective risk under the SLA and pays for it in review rate. See moderation.

T

Temperature scaling — dividing the logits by a scalar T before softmax to recalibrate confidence, fitted on a held-out calibration split and frozen. Because MSP is monotone in the margin, temperature cannot reorder a binary model, so AURC is exactly T-invariant on the linear probes (verified bit-identical for T ≥ 0.5). It is not invariant on the trained checkpoints, whose large margins let saturation move the ranking — a corrected claim. See how experiments lie.

Threat model (tensor vs file) — who the attacker is. A tensor-access attacker can perturb the decoded image in memory; an ACE perturbation of 0.10–0.45 grey levels (below one 8-bit step) works for them. A file-access attacker can only upload a PNG/JPEG, so the perturbation must survive uint8 quantisation — the realisable moderation threat model. Every attack row must say which it assumes. See attacks and moderation.

TRADES — a defense that trades clean accuracy against robustness via a regularizer pulling adversarial and clean predictions together. One of the three defended arms; at 2/255 it holds under attack (0.7062) but starts from a lower clean accuracy (0.7877) than PGD-AT. See defenses.

TRAIL Factory brick — the project's framing of WP1's deliverable as a reusable component: a data-agnostic scoring "brick" other work packages plug into. Grounded in the code — metrics.py consumes only plain arrays (scores, labels), never a dataset or a model, so a second dataset is a data adapter rather than a rebuild. See the harness.

TReC 2026 — the research camp this work is built for (Lausanne, 24 Aug – 4 Sep 2026; final talk 4 Sep), on trustworthy AI and robustness. PIs: Sournac and Ben Jmaa. See the project and to 4 Sep.

U

uid — see img_id vs uid above.

uint8 quantisation — rounding a perturbed image back to the 8-bit pixel grid (round(x × 255) / 255) that any saved file must live on. It is what separates the two threat models: sub-step ACE perturbations are erased outright by it (the control, eps=0.0005, vanishes), while at eps 0.002–0.005 a quarter of images keep a full grey level and the attack survives. See attacks.

W

WP1–WP4 — the project's work packages. WP1 is this evaluation harness (metrics, risk-coverage, attacks-as-conditions). WP2/WP3 hand over prediction arrays from attacked or robustly-trained models. WP4 is the selective-moderation layer (SLA, residual risk, review rate). They interoperate only through the npz prediction contract, so no work package reads another's code. See the project.
